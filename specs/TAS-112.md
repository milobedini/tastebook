# Add a text area to Dino

Linear: TAS-112

## Summary

Dino has a one-line `Input` but nothing for longer text, and the recipe form (TAS-114 (Add a private recipe) and TAS-117 (Method steps and equipment)) needs one for a recipe's description and its method steps. This adds `TextArea` to Dino: a multi-line field that plugs into `Field` like `Input`, has the same five states, and grows taller with its text instead of scrolling. Nothing renders it yet, so nobody in production sees a change until TAS-114 uses it.

Evidence: chore — no page uses the text area yet; its stories and their baselines show each state.
Design: needed — `docs/design.md:230` (Still to settle) leaves the text area to be designed when a project needs it, and no Dino board draws it (`docs/design/dino/fields.dc.html` has only one-line fields).
Components: TextArea (new)

## Product behaviour

1. The text area shows a visible label above it, and shows an error state and a disabled state.
2. Someone can reach and type in it by keyboard with a visible focus ring, and it reflows at 320 CSS px without scrolling sideways.
3. Stories show default, hover, focus, invalid, disabled, growing with its text and inside a labelled field.

## Technical design

- **Approach:** frontend only, all in `frontend/src/dino/`. A new `TextArea` (`text-area.tsx`) renders a `<textarea>` with the field look. Its classes for hover, focus, invalid and disabled are the third copy of those in `Input` and `NativeSelect`, so they move with `isAriaDisabled` into a new internal module, `field-control.ts`, that all three use. The text area grows with its text through CSS (`field-sizing: content`), with no script. The approved design lands as a Dino board, `docs/design/dino/text-area.dc.html` and its PNG, and `docs/design.md` gains a Text area row and loses the text area from Still to settle.
- **API contract:** no change.
- **Blast radius:** see [Blast radius](#blast-radius).
- **Not changing:** `Field`, `SearchInput`'s behaviour, the look of `Input` and `NativeSelect`.

### The shared field states

```ts
// frontend/src/dino/field-control.ts (new, not exported from index.ts)
import type { AriaAttributes } from 'react';

export const isAriaDisabled = (value: AriaAttributes['aria-disabled']) => value === true || value === 'true';

// Hover, focus, invalid and disabled for every text field (docs/design.md, States).
export const fieldControlStates = [
  'hover:not-aria-invalid:not-aria-disabled:border-muted',
  'focus-visible:not-aria-invalid:border-ink focus-visible:outline-1 focus-visible:outline-offset-0 focus-visible:outline-ink',
  'aria-invalid:border-danger',
  'aria-disabled:cursor-not-allowed aria-disabled:border-dashed aria-disabled:bg-surface aria-disabled:text-muted',
  'forced-colors:aria-disabled:border-[GrayText] forced-colors:aria-disabled:text-[GrayText]'
];
```

`Input` and `NativeSelect` pass `...fieldControlStates` to `cn` in place of their four state lines, and import `isAriaDisabled` from it in place of their own. The strings are byte-for-byte the ones in `input.tsx:17-21` today, so Tailwind generates the same CSS.

### TextArea

```ts
// frontend/src/dino/text-area.tsx
import type { ComponentProps } from 'react';

// Disabled is aria-disabled, never disabled, so the field stays focusable (docs/design.md, States).
type TextAreaProps = Omit<ComponentProps<'textarea'>, 'disabled'>;

export const TextArea = ({ className, readOnly, ...props }: TextAreaProps) => (
  <textarea
    readOnly={readOnly || isAriaDisabled(props['aria-disabled'])}
    className={cn(
      'block w-full min-w-0 min-h-24 field-sizing-content resize-y supports-[field-sizing:content]:resize-none rounded-card border-2 border-field bg-transparent px-4.5 py-2.5 font-bold text-body text-ink transition-colors placeholder:font-semibold placeholder:text-muted',
      ...fieldControlStates,
      className
    )}
    {...props}
  />
);
```

- The base line above is the provisional look: Input's border, type, colours and horizontal padding; 10 px top and bottom padding, so the first line sits where Input's text does; a 96 px minimum height (three lines of Body at 24 px, plus padding and border); 24 px corners. The approved design replaces the corner (`rounded-*` token), padding and minimum height if it draws them differently. Use only the corner tokens in `picnic.css` (`tools/biome/` rejects an arbitrary radius).
- **Grows with its text:** `field-sizing: content` makes the box as tall as its text, never shorter than `min-h-24`. There's no maximum height: the page scrolls, not the field. Where a browser lacks `field-sizing` (Firefox at the time of writing), the field keeps its minimum height, scrolls inside, and can be dragged taller (`resize-y`); where it has it, the drag handle goes (`supports-[field-sizing:content]:resize-none`).
- **Disabled:** `aria-disabled` makes it read-only, as in `Input`: focusable, its text selectable, not editable.
- **Keyboard:** native. Tab reaches it, Enter adds a line, Tab leaves it.
- **Reflow:** `w-full min-w-0` fills its column at any width; a `<textarea>` wraps long words by default, so it never scrolls sideways.
- No `rows` prop default: `field-sizing: content` ignores `rows`, and the minimum height comes from the class.

### Blast radius

- `Input` (`input.tsx`) and `NativeSelect` (`native-select.tsx`) take their state classes and `isAriaDisabled` from `field-control.ts`. They are used across the app (`grep -rln "Input\|NativeSelect" frontend/src`). Safe because the class strings are identical and `cn` (tailwind-merge) receives them in the same order before `className`. Proof: every `dino-input--*`, `dino-searchinput--*`, `dino-nativeselect--*`, `dino-field--*` and `dino-combobox--*` baseline stays unchanged, and `pnpm test` passes untouched.

## Decisions

- The text area grows with its text, with no maximum height and no drag handle, because a method step reads best whole and the page already scrolls. Asked: How should the text area's height behave as someone types? → Grows with its text.
- It grows through CSS `field-sizing: content`, not a script measuring `scrollHeight`, because a script needs an effect or an input handler to resize, misses values set from outside (a form reset), and adds state; CSS needs none. A browser without it falls back to a fixed minimum height with a drag handle, which is still usable.
- Its corner is a rounded rectangle, not the fields' pill, because a pill on a box three lines tall clips the first and last lines' ends. The design stage picks the token; the spec starts from 24 px (`rounded-card`). This changes `docs/design.md`'s rule that fields are pills, so the doc says so in this PR.
- The state classes and `isAriaDisabled` move to `field-control.ts`, because the text area is their third use (`AGENTS.md`, abstract on the third). It stays internal to `src/dino/`, not exported from `index.ts`, since no other area needs it.
- `textarea` joins the 44 px target check in `preview.tsx`, because the check guards every focusable control a story renders and a text area is one; it costs nothing today.
- The board lands as its own file, `docs/design/dino/text-area.dc.*`, rather than an edit to `fields.dc.html`, because `fields.dc.png` is the board every field story compares against and redrawing it would put unrelated changes in front of review.
