# Checking a Vercel preview from GitHub Actions

- **Added:** 2026-10-26 · **Applies to:** triage | spec | implement | review · **Issue:** TAS-26
- **Rule:** Vercel creates a GitHub deployment per push, environment `Preview` or `Production`, with `ref` set to the commit SHA. A `deployment_status` workflow runs from the file at that SHA, so a new or changed one runs on its own PR's preview; `workflow_dispatch` can't, because GitHub only finds dispatchable workflows on the default branch. To get Lighthouse past the sign-in, set the bypass cookie in its browser first (`collect.puppeteerScript`, one request with `x-vercel-protection-bypass` and `x-vercel-set-bypass-cookie: true`) and give it no `extraHeaders`: Lighthouse fetches `robots.txt` without its extra headers, and sends them on every cross-origin request too, where a CORS preflight such as Sentry's refuses them. Keep the Vercel toolbar off for previews (project Settings › General › Vercel Toolbar › Preview: Off): Lighthouse can't skip it without headers, so it scores Vercel's injected scripts as if they were the app's. A same-origin request sent without credentials (`credentials: 'omit'`) leaves the bypass cookie behind too, so Vercel redirects it to `vercel.com/sso-api`; the browser logs the failed cross-origin request and Best Practices drops to 96. A `<link rel="manifest">` is one such request: browsers fetch the manifest without credentials even from the same origin, so it needs `crossorigin="use-credentials"`. The Playwright specs can't catch this class, because they send the bypass header on every request and headless Chromium doesn't fetch the manifest on load; only Lighthouse does. A change that adds such a request isn't proven until its own PR's preview checks have run.
- **Why:** On TAS-26 the triage brief expected the workflow to be provable only by a manual dispatch, which GitHub refused, while the `deployment_status` run on PR #24 worked. Without the cookie, Lighthouse read Vercel's sign-in page as `robots.txt` and held SEO at 86; once Sentry was added, the extra headers made its ingest request fail and held Best Practices at 96. Later the toolbar's `vercel.live` feedback script began setting a third-party cookie, which held Best Practices at 79 on every preview with no change to Tastebook. TAS-33's Sentry tunnel sent its reports without credentials and merged while Vercel's daily limit blocked previews, so every PR's preview failed Best Practices until TAS-55. TAS-82's manifest link, added without `crossorigin`, failed Best Practices the same way on PR #74.
