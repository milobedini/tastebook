# Add a switch to Dino

Linear: TAS-113

## Summary

Dino has no control for turning one thing on or off. TAS-119 (make a recipe public) and TAS-128 (share link) both need one, so this adds `Switch` to `frontend/src/dino/`: a visible label beside a Radix switch, on, off and disabled, usable by keyboard and announced as a switch, with a 44 px target and a story per state. `docs/design.md` (Still to settle) leaves the switch to be designed when a project needs it, so its look is drawn at the design stage before it's built; this spec settles its behaviour, its API and the rules the drawing must meet.

Evidence: chore — no page uses the switch until TAS-119 (make recipe public), so nobody in production sees it; the Switch stories and their two baselines each show every state.
Design: needed — `docs/design.md:227` lists the switch as designed when needed and no Dino board draws it, so its track, thumb, on state and row are new visual work.
Components: Switch (new)

## Product behaviour

1. The switch shows its label and looks different when off, on and disabled.
2. Keyboard users can tab to it, toggle it with Space, and see focus.
3. A screen reader announces it as a switch with its name and on or off.
4. Its target, the label and switch together, is at least 44 px tall.
5. Stories show off, on, hover, pressed, focus, disabled off and disabled on.

## Technical design

- **Approach:** frontend only. A new `Switch` in `frontend/src/dino/switch.tsx`, exported from `index.ts`, with stories in `switch.stories.tsx`. The preview's 44 px check learns that a switch's target is its label, as a checkbox's is. The approved design lands as a Dino board, named in `boards.ts`, and `docs/design.md` gains a Switch row in Components and drops "switch" from Still to settle.
- **API contract:** no change.
- **Blast radius:** `frontend/.storybook/preview.tsx`'s `afterEach` runs after every story. The change only adds `[role="switch"]` to the selector and the label lookup, and no story renders a `role="switch"` today (`grep -rn 'role="switch"\|Switch' frontend/src` finds none), so every existing story measures exactly as before. Re-check: `pnpm test` passes every story. `boards.ts` is read by `frontend/visual/stories.spec.ts`, whose "every story title has a board image" test fails until `Dino/Switch` names a board that exists.
- **Not changing:** `CheckboxRow`, `Checkbox`, `FilterChip` and `Button`; no page uses the switch yet.

### The component

```ts
// frontend/src/dino/switch.tsx
import { Switch as SwitchPrimitive } from 'radix-ui';

// A disabled switch must say why (docs/design.md, States › Disabled), so the reason is required with it.
type DisabledProps =
  | { disabled?: undefined; disabledReason?: undefined }
  | { disabled: boolean; disabledReason: string };

type SwitchProps = {
  children: string; // the visible label, also the accessible name
  checked: boolean;
  onCheckedChange: (checked: boolean) => void;
} & DisabledProps;

export const Switch = (props: SwitchProps) => { /* … */ };
```

Structure (classes come from the approved design):

```tsx
<>
  <label htmlFor={id} className="… min-h-11 … has-focus-visible:outline-3 has-focus-visible:outline-ink …">
    <span className="grow">{children}</span>
    <SwitchPrimitive.Root
      id={id}
      checked={checked}
      onCheckedChange={handleCheckedChange}
      aria-disabled={disabled || undefined}
      aria-describedby={disabled ? reasonId : undefined}
      className="… focus-visible:outline-none …" // the row carries the ring
    >
      <SwitchPrimitive.Thumb className="…">
        {checked && <Check aria-hidden="true" … />}
      </SwitchPrimitive.Thumb>
    </SwitchPrimitive.Root>
  </label>
  {disabled && <p id={reasonId} className="flex items-start gap-2 text-small text-muted"><Info aria-hidden="true" … />{disabledReason}</p>}
</>
```

- `id` and `reasonId` come from `useId()`.
- `handleCheckedChange = (next: boolean) => { if (!disabled) onCheckedChange(next); }`. The switch is controlled, so dropping the call leaves it as it was, whether pressed with the pointer, Space or Enter, or through its label.
- Radix renders `<button type="button" role="switch" aria-checked>`; a `label htmlFor` naming a button forwards its clicks, as `CheckboxRow` relies on today. The accessible name is the label's text; the description is the reason.
- `disabled` is never passed to Radix's own `disabled`, which would make the switch unfocusable; it becomes `aria-disabled` (docs/design.md, States › Disabled).
- The label text and the switch sit in the order and alignment the approved design draws. If the design leaves it open: label first, switch at the row's end.

### Rules the design must meet

These go to the design stage with the spec, and implement checks the drawing against them.

- Every state from States: off, on, hover, pressed (a 97% to 94% shrink, drawn on the switch or the row), focus (a 3 px Ink ring, flush, round the row as on the checkbox row, never standing off a pill), disabled off and disabled on (Surface fill, dashed Field border, Muted label, the reason line under it).
- On means chosen, so on is mint (Colour; Rules › Colour), with a check icon in `currentColor` as well as the fill (Rules › State) and the thumb at the other end, so the state never rests on colour alone.
- Off's track border is Field, at least 3:1 against Ground (WCAG 1.4.11); the mint track keeps a 2 px transparent border, so forced colours draws it (Rules › Shape).
- Pill corners for the track and a round thumb; the thumb slides in 120 ms ease-out, and not at all under `prefers-reduced-motion` (Space and shape › Motion).
- The row is at least 44 px tall (Rules › Touch and motion); the label is Body in Ink.
- A forced-colours drawing of off, on and disabled.

The stories are the tests: `pnpm test` runs each in Chromium with axe and the 44 px check. `meta.args` are `children: 'Public'`, `checked: false`, `onCheckedChange: fn()`; `disabledReason` is `'Add a photo before making it public.'`.

  - `IsOn` (`checked: true`): asserts: `getByRole('switch', { name: 'Public' })` `toBeChecked()` and `toHaveAttribute('aria-checked', 'true')`.
  - `IsHover` (`parameters: isHover`): no play; its baseline shows the hover look.
  - `IsPressed` (`parameters: isPressed`): no play; its baseline shows the pressed look.
  - `IsFocus` (`parameters: { pseudo: { focusVisible: ['button[role="switch"]'] } }`): no play; its baseline shows the ring on the row.
  - `IsDisabled` (`disabled: true`, `disabledReason`): tabs, asserts: the switch `toHaveFocus()`, `toHaveAttribute('aria-disabled', 'true')` and `toHaveAccessibleDescription('Add a photo before making it public.')`; clicks it and presses Space, asserts: `args.onCheckedChange` `not.toHaveBeenCalled()` and the switch `not.toBeChecked()`.

## Decisions

- **Design: needed**, because `docs/design.md` (Still to settle) says the switch is designed when a project needs it and no board draws it; the doc decides the behaviour, so the design stage draws only the look.
- **Wrap Radix `Switch`** rather than a native `<input type="checkbox" role="switch">`, because `Checkbox` already wraps Radix (`radix-ui` is a dependency) and Radix gives `role="switch"` and `aria-checked` with Space and Enter handled; a native input would be the only one of its kind in Dino.
- **One component holding the label and the switch**, with the label required as `children`, because the criteria ask for a visible label and the 44 px target is the row (as `CheckboxRow`); a bare unlabelled switch would let a caller ship one without a name. A separate bare `Switch` primitive waits for a second shape that needs it.
- **Disabled is `aria-disabled` with a required reason line**, because `docs/design.md` (States › Disabled) says a disabled control stays focusable and says why, and `Button` already types the reason as required with `disabled`. The union type is written again here rather than shared: this is its second use (rule of three).
- **The ring sits on the row, not the switch**, mirroring `CheckboxRow`, because the row is the target and the doc forbids a ring standing off a pill.
- **The 44 px check measures a switch's label**, because a switch's track is shorter than 44 px by design and its target is the whole row, exactly as for a checkbox.
- **No help text prop**, because neither criterion asks for one and the reason line covers the disabled case; TAS-119 can add one if its design needs it.
